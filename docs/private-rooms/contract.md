# Private rooms contract1.0.0

Route `/clash/rooms`, reachable from `/clash/modes`. Guests create an opaque16character invite capability; another browser joins by possessing that invite. Members may read a private room's casual margin board and completed-result feed. Nonmembers receive403 with no room content. A result must belong to the current guest session before entry; clients never provide scores. Concurrent mutations are serialized with an expiring store lock and a human retry error. This is a KV membership boundary, not Supabase RLS.

The feed includes explicitly public completed-result cards and live governed Challenge invitations owned by a verified account. The existing Challenge system owns acceptance, comparison and ratings; the room only links to it. Account-owned results can enter from another device through server-only ownership mapping; another account sharing the original cookie is still refused. Real provider/browser verification and email delivery remain release blockers. The room notification hook requires both verification flags and an injected sender and stays disabled. No email is sent by this release.

Local tests cover nonmember refusal, forged result refusal, same-owner entry and concurrent join retry. Local fake-cloud tests cover two account identities, cross-device result ownership and owned-versus-foreign Challenge invitations. A real two-account Preview browser journey and persistent-store failure behavior remain unverified until credentials are available. The invite is a private access capability: share only with intended players. Never expose it to public metadata or analytics.
